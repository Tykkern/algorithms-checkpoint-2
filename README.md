# Контрольная точка 2: задачи на массивы и строки

Практикум по алгоритмам. Шесть задач на хеш-таблицы, два указателя, скользящее
окно и префиксные суммы. Решения на Java.

| № | Задача | Класс | Подход | Время | Память |
|---|---|---|---|---|---|
| 1 | Самая длинная последовательность номеров | `LongestSequence` | HashSet | O(n) | O(n) |
| 2 | Тройки с нулевой суммой | `ZeroSumTriples` | сортировка + два указателя | O(n²) | O(n) |
| 3 | Самый длинный участок с ограниченным числом типов | `TwoTypesSegment` | скользящее окно | O(n) | O(1) |
| 4 | Количество подмассивов с заданной суммой | `SubarraySum` | префиксные суммы + HashMap | O(n) | O(n) |
| 5 | Максимальный объём воды между стенками | `WaterContainer` | два указателя | O(n) | O(1) |
| 6 | Минимальная подстрока-покрытие | `MinCoveringSubstring` | скользящее окно | O(n + m) | O(1) |

## Запуск

Нужен JDK 17 или новее, Gradle скачается сам через wrapper.

```
gradlew test    # тесты
gradlew run     # прогон примеров из задания
```

На Linux и macOS: `./gradlew test`, `./gradlew run`.

На Windows проект лучше держать в папке без кириллицы в пути. Иначе Gradle
не находит тестовые классы (`ClassNotFoundException`), хотя они скомпилированы.

## 1. Самая длинная последовательность номеров

Все числа кладутся в `HashSet`, повторы при этом отпадают сами. Дальше для каждого
числа `x` проверяем, есть ли `x - 1`. Если есть, то `x` стоит в середине
последовательности и мы его пропускаем. Если нет, то `x` начинает
последовательность, и мы идём вверх `x + 1`, `x + 2`, ... пока числа есть в множестве.

Каждое число попадает во внутренний цикл только один раз, из своей
последовательности, поэтому общее время O(n). Сортировка дала бы O(n log n).

## 2. Тройки с нулевой суммой

Сортируем копию массива (исходный не меняется). Перебираем первый элемент `a[i]`,
а пару к нему ищем двумя указателями на отрезке справа: если сумма меньше нуля,
левый указатель идёт вправо, если больше, правый идёт влево.

Повторы убираются без множества: одинаковые значения `a[i]` пропускаются,
и после найденной тройки указатели проходят мимо одинаковых чисел. Если
`a[i] > 0`, цикл можно заканчивать, потому что дальше числа только больше.

O(n) итераций внешнего цикла по O(n) шагов указателей дают O(n²). При n = 3000
это около 9 миллионов шагов.

## 3. Самый длинный участок не более чем с двумя типами

Скользящее окно `[left, right]` и словарь «тип -> сколько штук в окне».
Правая граница сдвигается на каждом шаге. Если в окне оказалось три типа, левая
граница сдвигается, пока один тип не исчезнет из окна полностью. После этого окно
снова подходит, и его длина сравнивается с лучшей.

Каждый элемент один раз входит в окно и один раз из него выходит, поэтому O(n).
В словаре не больше трёх ключей.

## 4. Количество подмассивов с суммой k

Пусть `prefix[j]` равно сумме первых `j` элементов. Сумма подмассива между
позициями `i` и `j` равна `prefix[j] - prefix[i]`. Подмассив с суммой `k`,
который заканчивается в `j`, означает, что раньше была префиксная сумма
`prefix[j] - k`. Поэтому идём по массиву, считаем текущую префиксную сумму
и прибавляем к ответу, сколько раз уже встречалась сумма `sum - k`. Пустой префикс
с суммой 0 кладём в словарь заранее, иначе не посчитаются подмассивы от начала.

Скользящее окно тут не работает: из-за отрицательных чисел сумма окна не растёт
при расширении.

Переполнение. Префиксная сумма доходит до 2 * 10^5 * 10^9 = 2 * 10^14, а ответ
может быть n * (n + 1) / 2, около 2 * 10^10 (например, массив из нулей и k = 0).
Оба значения не помещаются в `int`, поэтому суммы, `k` и ответ хранятся в `long`.

## 5. Максимальный объём воды

Указатели ставим на края. Считаем объём `(right - left) * min(height[left], height[right])`
и сдвигаем указатель у более низкой стенки.

Почему так можно. Пусть левая стенка ниже правой. Любой контейнер с этой левой
стенкой и какой-то стенкой ближе правой будет уже, а вода в нём всё равно не выше
левой стенки. Значит, лучше уже посчитанного объёма левая стенка не даст, и её
можно отбросить. Так за один проход перебираются все пары, которые могут дать
ответ, O(n).

Объём до 2 * 10^5 * 10^9 тоже не помещается в `int`, считается в `long`.

## 6. Минимальная подстрока-покрытие

Скользящее окно и массив `need`: сколько каждого символа ещё не хватает в окне
(отрицательное значение значит, что символ в окне лишний). Счётчик `missing`
показывает, сколько символов `target` всего не хватает.

Правая граница добавляет символ в окно. Когда `missing` становится 0, окно
покрывает `target`, и мы сжимаем его слева, пока покрытие сохраняется, запоминая
самое короткое. Если таких окон несколько, возвращается самое левое. Если
покрытие так и не нашлось, ответ пустая строка.

Регистр учитывается автоматически, потому что `'A'` и `'a'` разные значения
`char`. Массив `need` заведён на все значения `char`, поэтому решение не упадёт
и на символах вне латиницы и цифр. Время O(n + m), где n и m длины `source`
и `target`.

## Тесты

На каждую задачу есть:

- примеры из задания;
- граничные случаи (пустой массив, один элемент, повторы, отрицательные числа,
  нет ответа, регистр символов);
- сверка с переборным решением на 500 случайных входах;
- вход максимального размера из ограничений с таймаутом 5 секунд, в задачах 4 и 5
  он заодно проверяет, что ответ больше `int` считается правильно.
